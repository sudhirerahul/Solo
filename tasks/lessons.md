# Lessons

Format: [date] | what went wrong | rule to prevent it

This file is read at the start of every session per global CLAUDE.md workflow. Add an entry any time an approach is corrected so the next session doesn't repeat it.

[2026-07-25] | Assumed the already-authenticated Notion/Slack MCP connectors pointed at the real client workspace and spent two recon agents confirming SFP data there before checking; both were sandbox/unrelated accounts | Verify connector workspace identity (Slack team domain, Notion top-level page/database titles) before trusting any connector-derived data as real, especially before spending agent calls on data-dependent recon.

[2026-07-25] | The RSVP reminder-tracking prompt judged capacity off confirmed RSVPs alone; a dry run against a fixture with confirmed exactly at capacity plus one tentative guest showed this would miss a room that's already oversubscribed | Always sum confirmed + tentative against venue capacity when flagging capacity, never confirmed alone (see `cowork/rsvp-reminder-tracking.md`).

[2026-07-25] | The post-event follow-up prompt had no rule for a single attendee note that mixes a routine detail with a high-stakes one (e.g. a harmless slide-feedback ask sitting next to a disclosed fundraise/payroll problem in the same fixture bullet) — as written it risked either suppressing the whole draft or leaking the sensitive half into an outgoing note | When a note mixes routine and high-stakes content, split it: draft the thank-you from the routine portion only, escalate the high-stakes portion separately — never fold both into a single decision (see `cowork/post-event-follow-up.md`).

[2026-07-25] | "Claude Code Routine" was initially assumed self-configuring via the `CronCreate` tool inside a session, but that tool is session-only, in-memory, and auto-expires after 7 days — not durable | Durable repo-triggered automation = a GitHub Actions workflow using `anthropics/claude-code-action@v1`, never `CronCreate` (see `.github/workflows/show-notes-drafting.yml`).

[2026-07-25] | Two variants of show notes drafting (Cowork + Routine) were maintained in parallel with no decision recorded, creating ambiguity about which one is actually running | When a surface decision is made, delete the losing variant in the same change and record the decision with a date in the surviving file — don't leave deprecated tombstones (see `routines/show-notes-drafting/PROMPT.md`).

[2026-07-25] | Post-meeting-action-extraction's dedup rule said "same source meeting + date" without specifying which date (meeting date vs. the Date-extracted run-date column) — a meeting re-scanned on a later calendar day could have duplicated | Dedup key is now explicit in the prompt: same Source meeting + same meeting date, never Date extracted (see `cowork/post-meeting-action-extraction.md`).

[2026-07-25] | Ran a synthetic golden-dataset calibration of post-meeting-action-extraction + open-commitments-digest (no real meeting data exists yet) and independently verified the executor's self-reported "perfect score" rather than trusting it — the self-report held up (7/7 recall, 0 fabrication, correct dedup, correct digest flags) but the verifier still found two real gaps the self-report glossed over: (1) the dedup test only covered same-calendar-day pre-seeding, not the older-date case that actually matters in production, and it was run and re-verified by the same agent in the same context; (2) the digest cited source meeting only for the unowned item, not for overdue items | Never accept a subagent's self-reported "all green" without an independent re-check that re-derives the answer from the source of truth itself (here: live Notion query + ground-truth file), and treat a same-context rerun as weaker evidence than a fresh-agent rerun. See `eval/post-meeting-action-extraction/` and the Calibration notes in both `cowork/post-meeting-action-extraction.md` and `cowork/open-commitments-digest.md`.

[2026-07-25] | The RSVP reminder-tracking prompt had no explicit rule for a blank/missing RSVP Status field — without one, a blank status could plausibly be skipped entirely or misread as an implicit confirmation | Blank or missing RSVP Status is always treated as "No response," never inferred as confirmed and never guessed from other fields (see `cowork/rsvp-reminder-tracking.md`).

[2026-07-25] | The post-event follow-up prompt had no rule for a guest who RSVP'd confirmed but didn't actually attend — without one, the prompt could plausibly have drafted a thank-you to someone who was never in the room, a real fabrication risk once cross-checked against Attendance | Always cross-check Attendance against the guest list before drafting: a confirmed guest recorded as a no-show gets no thank-you draft, only a flag to the Principal (see `cowork/post-event-follow-up.md`).

[2026-07-26] | The user stated there is no real Solo Founders Slack or Notion workspace at all — a materially different fact than the "connector points at the wrong workspace, reconnect it" framing this repo had been operating on since 2026-07-25. Every "Blocked" status and the "Open questions for the user" section in `tasks/todo.md` had assumed the real workspace exists and just isn't connected yet | Don't assume a connector blocker is temporary/reconnectable without the user confirming a real target exists; when told otherwise, treat synthetic dry-run/eval calibration as the durable calibration path, not a stopgap — and update every stale "Blocked — wrong workspace" status to reflect it (see the "Correction" note in `tasks/todo.md`, dated 2026-07-26).

[2026-07-26] | `cowork/morning-briefing.md` had no privacy/redaction rule at all before its first-ever dry run, and a build subagent found + fixed a real leak (a founder's private co-founder-departure disclosure landing verbatim in a possibly-shared-channel briefing) but did not re-run the fixture against its own fix before reporting done — the fix went unverified until the orchestrator re-ran it separately. This is the second automation (after `cowork/daily-rollup.md`) to hit this exact same missing-privacy-rule shape independently, discovered piecemeal rather than designed in from the start | (1) Any automation whose sources include Slack DMs, Gmail, or 1:1 notes should get an explicit personal/health/legal/financial-distress withholding rule built in from first draft, not discovered per-automation after the fact — check for one before the first dry run, not after. (2) When delegating a "find gaps, fix the prompt, note it" task to a subagent, explicitly require it to re-run the fixture against its own fix in the same task — "fixed and noted" is not the same as "verified," and a fix nobody re-ran is still an unverified claim.
